# Настраиваем подключение по SSH между машинами
Cоздать ключи и проверить доступ из foreman-main в foreman-managed для пользователя foreman-proxy.
```
#Создаем ключи для пользователя foreman-proxy
sudo -u foreman-proxy ssh-keygen -t rsa -b 4096 \
  -f /var/lib/foreman-proxy/.ssh/id_rsa_foreman_proxy
```
Далее добавляем содержимое `id_rsa_foreman_proxy.pub в /root/.ssh/authorized_keys на foreman-managed.`
Проверяем подключение
`sudo -u foreman-proxy ssh root@foreman-managed.ru-central1.internal`
Должно подключиться.

#!/bin/bash

apt-get update

# Роль Ansible
Роль должна запрещать вход от `root` на `foreman-managed`
Создадим
`/disable_root_login/tasks/main.yml`  
```yml
---
- name: Disable root ssh login            # Название задачи
  ansible.builtin.lineinfile:             # Модуль для поиска и изменения отдельной строки в файле
    path: /etc/ssh/sshd_config            # Путь к файлу, который меняем
    regexp: '^[#\s]*PermitRootLogin'      # Поиск нужной строки
    line: 'PermitRootLogin no'            # Устанавливаем нужно значение
    validate: '/usr/sbin/sshd -t -f %s'   # Проверить синтаксис перед применением
  notify: restart ssh                     # Вызываем хэндлер, если файл был изменен

```
`/disable_root_login/handlers/main.yml`
```yml
---
- name: restart ssh           # Имя хэндлера
  ansible.builtin.systemd:    # Модуль для управления сервисами
    name: ssh                 # Имя ssh сервиса в systemd
    state: restarted          # Перезапускаем ssh

```

# Пункт 5 про подход использования Foreman
В этой задаче Foreman используется как централизованная система управления хостами, их донастройкой и базовой конфигурацией. Host group позволяют объединить хосты по общим параметрам и применять к ним одинаковые настройки группы. Ansible позволяет автоматизировать конфигурации ОС и сервисов. В рамках данного тестового заднаия после регистрации хоста на нём выполняется настройка NTP через provision template, а через Ansible роль запрещается вход на хост под рутом.
Делаем вывод, что с помощью инструментов Foreman и Ansible мы можем централизированно, из одного места управлять серверной инфраструктурой. Автоматизировать настройку серверов, объединяя их в группы по общим признакам и затем быстро применять к ним требующиеся изменения.  Один раз описываем шаблон либо роль для Ansible, далее несколькими нажатиями в веб интерфейсе Foreman мы можем их применить.
Если рассуждать о плюсах и минусах, то из плюсов выделю управление серверами единым инструментом, автоматизацию настройки, уменьшение ручного труда (соответственно количества ошибок).
Из минусов - нужно знать и разбираться, как работать с Foreman, Ansible. Разбираться как это всё установить и грамотно настроить для удобства дальнейшего использования. Так же необходимо поддерживать всё это в рабочем состоянии, следить за обновлениями, корректной работой.
По поводу пункта, что делал руками (Docker+Nginx+Samba сервер раздачи) (не совсем понял, точно ли это для меня). Docker позволяет нам запускать приложения в изолированных контейнерах, управлять и следить за ними. Nginx обрабатывает запросы. Принимает, перераспределяет их между разными серверами. Samba позволяет организовывать общие каталоги с разграничением доступа.
Получается Foreman и Ansible решают задачи управления и автоматизации инфраструктуры, а Docker, Nginx и Samba решают конкретные/прикладные задачи. Они не заменяют друг друга.
